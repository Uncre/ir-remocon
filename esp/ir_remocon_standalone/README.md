# わたしの赤外線リモコン

ブレッドボードに回路を組み、手持ちのリモコンを覚えさせ、スマートフォンから家電を操作する教材です。
ESP32が操作画面と学習信号を持ちます。普段使うときにPCやPythonサーバを起動しておく必要はありません。

**初版は実機未検証です。講座で配布する前に、下の実機チェックを講師の機材で完了してください。**
対象は従来型ESP32-WROOM-32系の開発ボード（Flash 4MB以上）です。C3/S3などは対象外です。

## 完成するとできること

- 1台のESP32に最大12個のボタンを登録、送信、削除できます。
- 日本語の名前を付けられます（UTF-8で60バイト以内。一般的な日本語で20文字程度）。
- 学習は15秒待ちます。結果が画面に出て、電源を切っても保存信号が残ります。
- 送信は38kHz固定、波形は最大1024要素です。すべての家電への対応を保証するものではありません。

まず照明やテレビの単純なボタンで試しましょう。エアコンの長い信号、長押し、トグルビットを使う
リモコン、Bluetooth/RFリモコンは、学習できない・同じ操作を繰り返せない場合があります。
予約、目覚まし、外出先からの操作、複数ESP32管理、Wi-Fi設定画面はありません。

## 1. 部品を用意する

下記は新しく組む場合の部品例です。既存のGPIO13受信／GPIO4送信回路も使用できます。

| 部品 | 数 | 役割 |
|---|---:|---|
| ESP32-WROOM-32系開発ボード、4MB以上 | 1 | Wi-Fiと回路の制御 |
| データ通信対応USBケーブル | 1 | 書き込みと電源 |
| ブレッドボードとジャンパー線 | 一式 | はんだ付けせず回路を作る |
| TSOP38238 | 1 | 38kHzの赤外線を受信 |
| TSAL6200 | 1 | 赤外線を送信 |
| 2N3904（onsemiのTO-92品を想定） | 1 | LEDの電流を切り替えるNPNトランジスタ |
| 100Ω、1kΩ、10kΩの抵抗（1/4W） | 各1 | LED電流、ベース電流、起動時の消灯を制御 |
| 0.1µFセラミックコンデンサー | 1 | 受信部の電源を安定させる |
| 操作対象の家電と元の赤外線リモコン | 各1 | 学習と動作確認 |

TSOP38238は3.3Vで使用できる受信部で、端子は1=OUT、2=GND、3=VSです。
TSAL6200は940nmの赤外線LEDです。必ず手元の部品の型番とメーカー図面を確認します。
同じ見た目の部品でも端子の並びが違うことがあります。
資料：[受信部](https://www.vishay.com/docs/82491/tsop382.pdf)、
[赤外線LED](https://www.vishay.com/docs/81010/tsal6200.pdf)、
[トランジスタ](https://www.onsemi.com/pdf/datasheet/2n3903-d.pdf)。

## 2. 回路を組む

USBを抜いた状態で配線します。ブレッドボードは内部でつながる穴を持つ板です。
部品の足を同じ接続列へ挿して短絡させないよう、接続列と中央の溝を確認してください。
電源レールが途中で分断される製品もあります。

ESP32の「13」「4」はGPIO番号です。コネクターの端から数えた13番目・4番目ではありません。

### 受信部

| 接続元 | 接続先 |
|---|---|
| ESP32 3V3 | TSOP38238 VS（3） |
| ESP32 GND | TSOP38238 GND（2） |
| ESP32 GPIO13 | TSOP38238 OUT（1） |
| 0.1µFの両端 | 受信部のVSとGNDの間（近くに配置） |

丸い受光面の向きをメーカー図面と照合して端子番号を確認します。
受信部は3V3へ接続してください。ESP32のGPIOへ5Vを入れないでください。
電気条件の根拠：[ESP32データシート](https://www.espressif.com/sites/default/files/documentation/esp32_datasheet_en.pdf)。

### 送信部

```text
ESP32 3V3 ── 100Ω ── LEDのアノード(A)
                       LEDのカソード(K) ── トランジスタのC
ESP32 GPIO4 ── 1kΩ ── トランジスタのB
                         B ── 10kΩ ── GND
                         E ────────── GND
```

Cはコレクター、Bはベース、Eはエミッターです。トランジスタはGPIO4の小さな電流で
LEDへ流す電流を切り替えるスイッチとして働きます。100ΩはLEDに電流が流れすぎるのを防ぎます。
この3.3V回路での電流の目安は約18mAです（LED約1.3V、トランジスタ約0.2Vと仮定した計算）。
最初は家電の近くで試します。到達距離は実測で決めます。

LEDのA/K、トランジスタのE/B/Cを図面で確認し、すべてのGNDを共通につなぎます。
100Ωを省略しないでください。配線変更は電源を抜いて行います。

## 3. 書き込みの準備

このフォルダだけを別の場所へコピーして開発・配布できます。フォルダ名と`.ino`名は
`ir_remocon_standalone`に揃えてください。`.pio`、`.vscode`、個人の`secrets.h`は配布しません。

`secrets.h.example`を同じフォルダに`secrets.h`という名前でコピーし、SSIDとパスワードを入れます。
2.4GHzのWi-Fiを使います。講座会場では端末同士の通信を禁止していないネットワークを用意します。

```cpp
#pragma once
#define WIFI_SSID "自分のWi-Fi名"
#define WIFI_PASSWORD "自分のパスワード"
```

このファイルをSNSや配布ZIPへ含めないでください。書き込んだバイナリにもWi-Fi情報が含まれます。

### Arduino IDEで書く

1. ボードマネージャーに「esp32 by Espressif Systems」**2.0.17**を入れます。
   [公式インストール手順](https://docs.espressif.com/projects/arduino-esp32/en/latest/installing.html)。
2. ライブラリを次のバージョンに揃えます。
   ArduinoJson **6.21.5**、IRremoteESP8266 **2.8.6**、ESPAsyncWebServer **3.12.0**、AsyncTCP **3.5.0**。
   ESPAsyncWebServerとAsyncTCPはESP32Asyncのものを選びます。
3. `ir_remocon_standalone.ino`を開きます。付属の`.h`、`.cpp`、`partitions.csv`を同じフォルダに置きます。
4. ボードは「ESP32 Dev Module」、Flash Sizeは「4MB」、接続したシリアルポートを選びます。
   スケッチに置いた`partitions.csv`を使います。このファイルを省略しないでください。
   [独自パーティションの公式説明](https://docs.espressif.com/projects/arduino-esp32/en/latest/tutorials/partition_table.html)。
5. 検証してから書き込みます。接続待ちのままなら、ボードのBOOTボタンを押しながら開始し、
   書き込みが始まったら離します（ボードによって不要です）。
6. シリアルモニターを115200bpsにして、必要ならEN/RESETを押します。

初回起動は単体版専用の保存領域を作ります。**既存版を使っているESP32へ書くと、そのESP32は
単体版になります。元のFastAPIからは操作できなくなります。** 教材確認には別のESP32を推奨します。
パーティション変更で以前のファームのフラッシュ内データは保持されるとは限りません。
PC上の既存SQLite DBを移行する機能はありません。

### PlatformIOで書く場合

このフォルダをプロジェクトとして開きます。`secrets.h`を用意した上で以下を実行します。

```powershell
pio run -e esp32dev
pio run -e esp32dev -t upload
pio device monitor -b 115200
```

HTMLはファームウェアに含まれるため、`uploadfs`は不要です。
通常の更新では全Flash消去やパーティション変更を行わず、同じ設定で書き込みます。
全消去をすると学習データも消えます。

## 4. スマートフォンから操作する

スケッチ冒頭の `MDNS_HOSTNAME` で `.local` の前の名前を変更できます。
例えば `constexpr char MDNS_HOSTNAME[] = "ir-remocon-01";` とすると、
`http://ir-remocon-01.local/` で開けます。`.local` 自体は定数に含めません。
半角英数字とハイフンを使い、先頭・末尾は英数字、1〜63文字にしてください。
変更後は再書き込みが必要です。複数台では名前を重複させないでください。
シリアルモニターにはIPと、mDNS開始成功時に設定した名前を表示します。

1. スマートフォンをESP32と同じネットワークへ接続します。
2. `http://ir-remocon.local/`を開きます（httpsではありません）。
3. 開けない場合はシリアルモニターの`Open http://192.168.…/`のアドレスを使います。
4. 「照明をつける」などの名前を入れ、「学習を開始」を押します。
5. 受信部へ元のリモコンを向けて、ボタンを短く押します。
6. 「学習して保存しました」と出たら、登録済みリモコンの「送信」を押します。

「送信処理が完了」はESP32が送信処理を終えたという意味です。家電からの返事を受け取る仕組みは
ないため、家電が実際に動いたか確認してください。通信が途切れたときは自動で再送しません。
電源ボタンなどが二度実行されるのを避けるためです。

画面は操作中のみ短い間隔で状態を確認します。非表示時は止まり、再表示時に再確認します。
別端末で追加・削除した結果は「状態を確認」で読み直せます。
複数台を会場で使う場合は`.local`名が重複するため、各ボードのIPを使ってください。
認証はないので、信頼できるLAN内で使用し、ルーターのポート開放はしません。

## 5. うまく動かないとき

| 症状 | 確認すること |
|---|---|
| ポートが出ない | データ対応USBケーブルか、ボードのUSBシリアル用ドライバーがあるか |
| Wi-Fi待機が続く | SSID／パスワード、2.4GHz、電源。修正後は再書き込み |
| `.local`だけ開けない | シリアル表示のIPを直接使う |
| IPでも開けない | 同じLANか、ゲストWi-Fiの端末隔離がないか |
| 学習が時間切れ | 受信OUTがGPIO13か、部品の足の順、リモコンの電池と向き |
| 長すぎる信号の表示 | 短く押し直す。繰り返す場合はこの初版の対応範囲外 |
| 学習できたが家電が動かない | LEDのA/K、トランジスタのE/B/C、GPIO4、距離、38kHz対応か |
| 操作結果が不明 | 家電を目視し「状態を確認」。すぐに連打しない |
| 読み出せない信号 | その信号を削除し再学習。ほかの信号は維持される |
| 保存領域を開けない | `Storage: ERROR`を確認。自動消去はしない。全消去を試す前に講師へ相談 |

## 講師向け実機チェック

- [ ] 配線図と採用部品を照合して、USB接続後の発熱や異常がない。
- [ ] 初回起動で`Storage: OK`とIPが出る。PCなしのUSB給電でも起動する。
- [ ] スマートフォンで表示し、日本語名の学習から送信まで家電が反応する。
- [ ] 学習を15秒放置すると時間切れになり、次の操作ができる。
- [ ] 学習中に別端末から送信／学習するとビジーになり、信号が混ざらない。
- [ ] 12件登録、13件目の拒否、削除後の再登録を確認する。
- [ ] 再起動と通常のファーム更新後に保存信号が残る。
- [ ] Wi-Fi切断中の結果不明表示、Wi-Fi復帰後の再接続を確認する。
- [ ] 学習中の画面非表示・再表示と、操作中のESP32再起動を確認する。
- [ ] 使用する家電ごとに到達距離と向きを確認する。

## 開発用の構成と確認

`ir_remocon_standalone.ino`がWi-Fi／HTTP／赤外線を担当し、`signal_store.cpp`が信号を保存、
`web_ui.h`が画面を持ちます。追加のWebビルド工程はありません。
ファームウェア領域は2MiB、LittleFSの専用領域`irdata`は約1.9MiB。OTAはありません。
保存ファイルは1信号ずつ、版番号・名前・長さ・16bit little-endianの波形を持ち、
一時ファイルを書き終えてから正式名に変更します。失敗時に既存信号へ上書きしません。

API: `GET /`、`GET /api/status`、`GET /api/signals`、`POST /api/learn {"name":"…"}`、
`POST /api/send {"id":0}`、`DELETE /api/signals?id=0`。
変更要求には`X-IR-Request: 1`、POSTには`Content-Type: application/json`が必要です。
学習／送信は202で受け付け、起動IDと操作番号でその後の結果を照合します。

個人のWi-Fi情報なしでビルドだけ確認する場合：

```powershell
pio run -e compile_check
node tests/ui.test.cjs
```

`compile_check`はダミーWi-Fi設定なので実機へ書き込まないでください。
通常の`esp32dev`は`secrets.h`がなければコンパイルで止まります。
実行済みの検証と制約は[検証記録](VALIDATION.md)を参照してください。
